# Hexvault Art Style Guide (HD pixel art)

Target look: **high-quality HD pixel art in an anime RPG style, fantasy arcane-tech action
roguelite** — chibi heroes with big expressive eyes, crisp pixel clusters, strong silhouettes,
controlled hue-shifted palettes, readable at a glance in a crowded fight. The reference
character is **Vex, the Rift Ranger** (`tools/artgen/hd/heroes/ranger.py`, sheet
`assets/sprites/heroes/hd/ranger.png`); every hero is built with the shared kit
(`tools/artgen/hd/heroes/kit.py`) and compared against Vex before it ships.

Everything here is enforced by code where possible (`tools/validate_assets.py`,
`tools/asset_qa.py`, both run by `tools/check.py`).

## 1. Resolution and pixel density

| Thing | Rule |
| --- | --- |
| World unit | Gameplay works in world units (a floor tile is 16 units). Unchanged from the 16 px era, so physics, AI and level data did not move. |
| Density | HD art is drawn at **4 art pixels per world unit** (`hd_registry.DENSITY`). Recorded per asset as `"density"` in `assets/manifest.json`; `SpriteLib.apply()` scales the node by `1/density`. |
| Screen | Stretch mode `canvas_items`, integer scale, expand. At 1920×1080 (and 3840×2160, 2400×1080 phones) one art pixel = an exact whole number of screen pixels. At other sizes the pixel-aware shader (`shaders/flash.gdshader`) keeps edges clean instead of producing uneven pixel widths. |
| Mixed density | Allowed only during migration (16 px assets still render at 4× chunky). Never mix densities *inside* one sprite, never scale HD art by a non-integer in the art itself. |

### Canvas sizes (at density 4)

| Asset | Frame | Body inside the frame | Notes |
| --- | --- | --- | --- |
| Hero | 96 × 96 | ~44 × 60 px, feet on y = 76, centre x = 48 | Same frame for every animation so the anchor never moves |
| Small enemy | 64 × 64 | | |
| Medium enemy / elite base | 96 × 96 | | |
| Large enemy | 128 – 192 | | |
| Boss | 192 – 256 | | |
| Weapon | 96 × 48 | grip pivot recorded in the manifest | |
| Projectile | 16 – 64 | | |
| Floor / wall tile | 64 × 64 | | 16 world units |
| Pickup / icon | 32 – 64 | | |

Sizes follow the camera: the 480×270-unit view at 1080p shows a hero ~60 px tall, about 1/18
of the screen height — the same footprint the 16 px hero had, so gameplay readability did not
change. Pick the smallest canvas that holds the whole motion (weapon tips, capes, trails) with
a 2 px transparent margin; `asset_qa.py` fails any frame with opaque pixels on its border.

## 2. View, proportions, anchor

- **View:** side / three-quarter, characters face **right**; the game mirrors for left.
- **Heroes:** anime chibi, ~2.5 heads tall: head radius 13.5, torso 14.5, legs ~17 (base
  units, x figure scale k ≈ 1.2–1.35). Defaults in `kit.proportions()`; a hero may change k
  (a hulking Warden 1.35, a small Tinker 1.2) but keeps feet on the ground line and the body
  centred.
- **Face (anime profile):** heads face the same way as the bodies (side view, facing right).
  The face fills the front of the head: one big eye from the hand-made template
  `kit.EYE_SIDE` (lash flicked at the corner, iris graded dark to light, pupil, catch-lights),
  a short one-pixel brow above it, the nose tip and chin as part of the head silhouette, a
  tiny mouth and a rose blush line. Light, flat cel shading on skin. Never draw a second eye
  on a profile head. Hoods and helms are open at the front.
- **Hair:** big volume over the back and top of the skull, pointed bangs falling over the
  forehead, a side lock in front of the ear, a broken "shine ring" in the brightest shade. Styles: short, spiky, long, ponytail.
- **Near / far limbs:** the far arm and leg are drawn first and one shade darker (`bias=-1`).
- **Anchor:** frame centre = actor origin. Feet line constant across looping animations
  (QA: feet drift ≤ 3 world px, centre-of-mass jumps limited, silhouette IoU ≥ 0.55).

## 3. Palette

- Master palette: `tools/artgen/hd/palette.py` (generated by `make_palette.py`, frozen).
  24 ramps × 6 shades + 8 fixed colours. Index 0 = darkest (selout / deep shadow),
  5 = specular.
- Ramps are **hue-shifted**: shadows rotate toward blue, highlights toward yellow,
  saturation peaks at the midtone (pixel-art-studio `ramp()`).
- Budget: ≤ 56 colours per HD sheet (8 ramps × 6 shades + fixed accents; QA warning above that). A hero uses 6–8
  ramps.
- Every hero has **one dominant hue, one contrast hue, one accent** (Vex: teal coat,
  crimson scarf, amber visor/buckle). Skin, hair, leather and metal ramps are shared.
- Emissive accents (`glow_*`) are unshaded and reserved for eyes, lenses, magic and
  pickups so the player learns "glow = important".

## 4. Light, shading, outline

- **Light from the top-left, in front** (`canvas.LIGHT`). No exceptions per asset.
- Shading is per part (`HDCanvas.draw`): each part is a mask raised into a pseudo-3D dome
  from its distance field, lit with Lambert, then quantised to cel bands. Forms:
  `round` (bodies, heads), `cloth`, `skin`, `metal` (hard specular band), `plate`
  (bevelled flat: belts, books, armour plates), `flat`/`soft` (small parts, linings).
- **No pillow shading** (uniform dark rims); shadow follows the light.
- **Selout:** where a part overlaps an older one its edge takes the darkest shade (one
  lighter on the lit side). Older parts in the overlap's shadow drop one shade (contact
  shadow).
- **Outline:** a 1 px `ink` (#14101e) outline around the whole silhouette. Not around
  individual parts — those use selout.
- **No anti-aliasing against transparency** (alpha is binary; validated). Single isolated
  pixels are removed by `HDCanvas.despeckle()`; QA warns above 3 % specks.
- **No dithering on animated parts** (it shimmers). Large static surfaces (floors, boss
  arenas) may use ordered dithering.

## 5. Characters

Each important character needs its own silhouette, not a recolour, plus its own **iris
colour and hair colour** (anime characters are recognised by face colours as much as by
outfit):

| Lever | Examples |
| --- | --- |
| Head shape | pointed hood, horned helm, wide hat brim, bare head + hair silhouette |
| Body mass | long coat, heavy plate, robe to the floor, light tunic |
| Breakers | scarf tails, cape, backpack, tail, floating orbs, shoulder pads |
| Colour identity | one dominant hue per character, unique among heroes of the same class |
| Accent | visor, gem, rune, lantern — one glowing point |

Squint test: at 1× on the dungeon floor the hero must be recognisable from the flat
silhouette alone (`pixelstudio.Sprite.save_silhouette` or the QA preview).

## 6. Animation

| Animation | Frames | FPS | Notes |
| --- | --- | --- | --- |
| idle | 6 | 6 | breathing (pelvis 0–1 px), head follows one frame late, blink on one frame |
| run | 8 | 12 | contact / down / passing / up; arms counter-swing; scarf/coat stream back |
| dash | 4 | 16 | strong lean, legs extended, cloth trailing (looped while dashing) |
| skill | 6 | 12 | anticipation → action → hold on the key pose → recover |
| hurt | 3 | 12 | recoil away from the hit, eyes shut, recover |
| death | 8 | 9 | stagger → knees → fall → settle; last frames hold |
| attack (melee heroes / enemies) | 4–6 | 12–16 | windup slower than strike; hold impact |

Rules: fewer, better frames; integer offsets only; secondary motion (scarves, coats, hair)
uses the `sway` phase so it lags the body; every pose comes from the rig, so proportions
cannot drift between frames. Each animation's frame count, FPS, loop flag and the frame
size / density are stored in the manifest.

## 7. Effects and UI

- FX may use glows and additive blending in-engine, but the source art obeys the same
  palette and binary alpha. Post-processing must never blur the sprites.
- Screen shake, flashes and particle density respect *Settings → reduced effects*.
- UI keeps the pixel font; HD portraits in UI are shown at integer multiples of their
  density scale.

## 8. Pipeline checklist for a new asset

1. Design: silhouette sketch in code (masks only), squint test.
2. Pick ramps (dominant / contrast / accent + shared materials).
3. Draw parts back to front with `HDCanvas.draw`, details last.
4. Animate by poses (`rig.Pose`), not by redrawing.
5. Register the module (`hd_registry.py`) → `python tools/artgen/build.py`.
6. `python tools/check.py` (palette, alpha, grid, clipping, anchor, noise, metadata).
7. Look at it in game (`--tour`), fix, repeat. Update `docs/qa/asset_qa_report.md`.

External art (AI or hand-drawn) enters through `tools/artgen/import_external.py`: raw file
kept untouched in `art_src/raw/`, cleaned (background key-out, true-pixel recovery, alpha
hardening, despeckle, colour dedupe, de-halo, HD palette lock) into `art_src/processed/`,
with the prompt and settings stored next to it, then the same QA as generated art.
